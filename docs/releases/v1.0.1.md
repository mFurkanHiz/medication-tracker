# v1.0.1 — the first accepted release

Cut on 2026-10-08 from `main` at `214dee4` (CI run `37778332190`). Accepted by the owner
on 2026-10-05 ("kabul") after their own live test round on the production site and the
Sprint 7 work that came out of it. The tag `v1.0.1` points at that commit.

## Why the number is 1.0.1

`v1.0.0` exists on the rejected 2026-09-14 baseline of the earlier domain model. The
owner chose to leave history untouched: that tag stays as the retired baseline and the
first accepted release is `v1.0.1` (ADR 0017). From here the server line — API and web,
shipped together — moves as `v1.0.x`, `v1.1.0` and so on, and the mobile client is
tagged `mobile-vX.Y.Z` with the server version it is at parity with.

## What V1 is

A web release with mobile infrastructure in place (ADR 0015). The owner moved the
offline mobile client past V1 on 2026-10-04; acceptance rows 28 and 29 are `DEFERRED`
on that date, not met. Everything else in `docs/v1-acceptance.md` is `DONE`.

- Package-first inventory: every physical box is a record, every dose says which box
  paid for it, and a correction is an appended reversal that conserves the total.
- Effective-dated treatment plans: pause, end and restart are versions; the past is
  never rewritten; the latest started version governs a day, and nothing governs the
  days after it ends.
- Daily, selected-weekday, every-N-day, day-of-month and every-N-month patterns, with
  the month clamped to its last day.
- Exact fractional quantities end to end; no binary floating point anywhere.
- Count sessions with revisions, lending and returns, refill policy with the official
  and the actual run-out dates, coverage per medicine and per box.
- The household's own caution notes and "do not take with" tags, shown where the box is
  held and matched only by plain equality on the household's own words (ADR 0016).
- Adherence and inventory reports, household export, Turkish and English throughout.
- Log redaction, a global rate limiter, accessibility at WCAG A/AA, and an API that
  connects to PostgreSQL as a role confined to its own database.

## Operations

- Every merge to `main` deploys itself: tests, two images, the packaged migration proven
  on an isolated PostgreSQL, a verified pre-migration backup on the host, only this
  project's `api` and `web` containers restarted, the public site proven from outside.
- The API runs as `medication_tracker_app`, a PostgreSQL role that is not a superuser and
  is confined to this database (acceptance row 37, applied on 2026-10-05).
- `GET /api/version` reports the version and the commit the image was built from; the
  web footer shows the same number.

## Known gaps, stated

- Reminders exist on the phone only, and the phone has no release channel beyond a USB
  install from a computer that holds this repository (`docs/mobile-device-install.md`).
- The workspace sends each plan's latest version only; a future-dated edit leaves the
  in-between days without local reminders on the phone.
- A human screen-reader pass of the web has not been done; the automated audit is not a
  substitute.
- The bootstrap superuser still exists for the database container and the migration
  step, used over the container's local socket only.
